# CONN-CAMUNDA-MCP — Requirements

Every requirement this specification owns, with the proof that closes it. Delivery state and
public evidence for each ID are recorded in [`status.json`](status.json); this file defines what
each ID means. The design is in [`spec.md`](spec.md) and [`plan.md`](plan.md), the test contract
in [`test-spec.md`](test-spec.md), and the work order in [`tasks.md`](tasks.md).

| ID | Requirement | Verification |
|---|---|---|
| `CONN-CAMUNDA-MCP-R001` | **Connector reports its released version.** `camunda_mcp.__version__` equals the released `pyproject.toml` version and the bump configuration updates both. Caller chain: the installed `camunda-mcp` distribution metadata (`pyproject.toml` line 7) -> `__version__ = _v("camunda-mcp")` in `camunda_mcp/api_client.py:18`, imported by the code that builds `Api`; `camunda_mcp/__init__.py` defines no `__version__`. Shape: `camunda_mcp/api_client.py:18` takes `__version__` from `importlib.metadata.version`; the new test compares it with the `project.version` read from `pyproject.toml` and the bump configuration entry. | `tests/test_version.py::test_reported_version_matches_the_released_package` |
| `CONN-CAMUNDA-MCP-R002` | **One tool per API operation.** The server lists 65 tools: one `camunda7_<operation>` per Camunda 7 client method (39), one `camunda8_<operation>` per Camunda 8 client method (24), plus `camunda_deploy` and `camunda_ingest_processes`. Caller chain: the `camunda-mcp` console script (`scion_sdk.cli:serve`) loads `camunda_mcp:connector` (`camunda_mcp/__init__.py:85`); its `verbose_targets` prefixes `camunda7` and `camunda8` yield one tool per client method, and `camunda_mcp/mcp/mcp_camunda.py` registers `camunda_deploy` (line 50) and `camunda_ingest_processes` (line 83). Shape: `verbose_targets` bind `Camunda7Api` (`api/api_client_camunda7.py`) and `Camunda8Api` (`api/api_client_camunda8.py`) to the SDK per-method tool generator; `camunda_mcp/mcp_server.py` exports `register_camunda_tools`. | `tests/test_tool_surface.py::test_surface_is_one_tool_per_operation_plus_two` |
| `CONN-CAMUNDA-MCP-R003` | **No condensed action facades.** No tool is tagged `split-action`, and no `camunda_*` tool routes an `action` string to an operation a `camunda7_*` or `camunda8_*` tool already serves. Caller chain: the `camunda-mcp` console script (`scion_sdk.cli:serve`) -> `camunda_mcp:connector` (`camunda_mcp/__init__.py:85`) -> SDK `build_server` -> the tools in `camunda_mcp/mcp/mcp_camunda.py` and the generated `camunda7_*` and `camunda8_*` tools. Shape: the only hand-written tools are `camunda_deploy` and `camunda_ingest_processes` in `camunda_mcp/mcp/mcp_camunda.py`; the test lists tools from `build_server("camunda_mcp")` and checks each tool tag set for `split-action`. | `tests/test_tool_surface.py::test_no_split_action_facade_tools` |
